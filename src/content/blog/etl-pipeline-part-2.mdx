<H1>Stage 1: Extract</H1>

<Paragraph>Let's begin implementing the first stage of our ETL pipeline: <Highlight>Extraction</Highlight>.</Paragraph>

<Paragraph>Remember, extraction is simply about retrieving data from our source systems. In our project, the source is four CSV files.</Paragraph>

<Paragraph>We use <Highlight>Pandas</Highlight> to read each file into a DataFrame.</Paragraph>

<CodeSnippet
  filename='extract.py'
  lang='python'
  code={`from pathlib import Path

import pandas as pd

# PROJECT_ROOT is the main ecommerce_etl folder.
PROJECT_ROOT = Path(__file__).resolve().parents[1]

CSV_FILES = {
    "customers": "customers.csv",
    "products": "products.csv",
    "orders": "orders.csv",
    "order_items": "order_items.csv",
}

def extract_data():
    # raw_data is a dictionary
    # It will hold name of the file as a key and its dataframe as a value
    raw_data = {}

    for key, filename in CSV_FILES.items():
        raw_data[key] = pd.read_csv(PROJECT_ROOT / "data" / "raw" / filename)

    return raw_data
`}
/>

<Paragraph>The extracted data isn't necessarily ready to be used. We may encounter missing values, duplicate records, inconsistent formats, or incorrect data types.</Paragraph>

<Highlight>Standardizing Text</Highlight>

<CodeSnippet

for column in ("customer_name", "city"):

df["email"] = df["email"].str.strip().str.lower()
`}

<Paragraph>We clean up extra spaces in customer names and cities. Small inconsistencies cause real problems, "karachi," "Karachi," and "KARACHI" should all be the same city. Standardizing text keeps things consistent.</Paragraph>

<CodeSnippet

  df["price"] = pd.to_numeric(df["price"], errors="coerce")

# .clip(lower=0) replaces negative prices with 0.

`}

<Paragraph>Not every value that looks like a number is actually stored in a numeric format. We convert prices into numeric values and replace negative values with 0.</Paragraph>
<Paragraph>However, handling negative values depends on business requirements and the context of the dataset. In some cases, they may need to be replaced with NULL or handled differently rather than simply set to zero.</Paragraph>

<BulletList items={[

<Paragraph>Let's break down how the loading process works.</Paragraph>

<H2>Insert or Update, Never Duplicate</H2>

<Paragraph>We use an upsert instead of a plain insert. This means we insert new rows and update existing rows when the primary key already exists.</Paragraph>

<Paragraph>But first, what is UPSERT?</Paragraph>

<Paragraph>UPSERT combines two operations:</Paragraph>

<NumberList items={[
  "**INSERT**: If a record doesn't already exist, insert it",
  "**UPDATE**: If a record with the same primary key already exists, update its values."
]}
/>

<Paragraph>This is useful because running the pipeline multiple times shouldn't create duplicate records.</Paragraph>

<CodeSnippet
  filename='load.py'
  lang='python'
  code={`query = text(f"""
    INSERT INTO {table_name} ({columns})
    VALUES ({placeholders}) AS new_values
    ON DUPLICATE KEY UPDATE {update_clause}
""")

connection.execute(query, records)
`}
/>

<Paragraph>What's happening here?</Paragraph>

<BulletList items={[
  "**INSERT INTO** specifies the target table and columns where records should be inserted",
  "**VALUES** provides placeholders for the incoming records",
  "**ON DUPLICATE KEY UPDATE** updates an existing record if its primary or unique key already exists, instead of inserting a duplicate",
  "execute() sends the query and the DataFrame records to MySQL"
]}
/>

<Paragraph>For example, suppose customer 101 already exists in our database, but their city changes from Karachi to Lahore.</Paragraph>

<Paragraph>Instead of inserting another customer record, UPSERT updates the existing record.</Paragraph>

<Panel type='info'>
  For learning purposes, this project uses both loading styles: <Highlight>orders</Highlight> are loaded incrementally, while <Highlight>customers</Highlight>, <Highlight>products</Highlight>, and <Highlight>order_items</Highlight> are loaded in full on each run.
</Panel>

<H2>Incremental Loading of Orders</H2>

<Paragraph>We'll implement incremental loading for the orders dataset.</Paragraph>

<Paragraph>Why?</Paragraph>

<Paragraph>Imagine having a database with thousands of orders. Every time the pipeline runs, loading all historical orders again would be unnecessary.</Paragraph>

<Paragraph>Instead, we only want to load nnewly created orders and existing orders that have been modified since the previous pipeline run.</Paragraph>

<Paragraph>To achieve this, I used a concept called <Highlight>Watermarking</Highlight>.</Paragraph>

<H3>What is a Watermark?</H3>

<Paragraph>A watermark is a reference point that tracks how far a data pipeline has processed its source data.</Paragraph>

<Paragraph>In this project, we use the <Highlight>updated_at</Highlight> column to identify new or modified orders.</Paragraph>

<CodeSnippet
  filename='load.py'
  lang='python'
  code={`# Return the newest updated_at already loaded for orders.
def get_watermark(connection, oldest_order_created_at):
    """Return the newest updated_at already loaded for orders."""

    result = connection.execute(text("""
        SELECT last_watermark
        FROM etl_watermarks
        WHERE pipeline_name = 'orders'
    """)).scalar()

    if result:
        return pd.Timestamp(result)

    return pd.Timestamp(oldest_order_created_at)
`}
/>

<Paragraph>Before loading new or updated orders, the pipeline needs to identify where the previous run stopped. <Highlight>get_watermark()</Highlight> retrieves the last saved timestamp from the <Highlight>etl_watermarks</Highlight> table. If no watermark exists, it uses the earliest created_at timestamp from the source data to ensure the first run captures all orders.</Paragraph>

<CodeSnippet
  filename='load.py'
  lang='python'
  code={`def get_oldest_order_date(connection):
    """Return the oldest created_at found in raw_orders"""

    result = connection.execute(text("""
        SELECT MIN(created_at)
        FROM raw_orders
    """)).scalar()

    if not result:
        raise ValueError("No orders founds")

    return result
`}
/>

<Paragraph><Highlight>get_oldest_order_date()</Highlight> finds the earliest created_at value in raw_orders. This gives the pipeline a sensible starting point when no watermark exists yet. If raw_orders is empty, it raises an error because there is no date to start from.</Paragraph>

<CodeSnippet
  filename='load.py'
  lang='python'
  code={`# Move the bookmark forward to the newest loaded updated_at.
  def save_watermark(connection, watermark):

    connection.execute(text("""
        INSERT INTO etl_watermarks (pipeline_name, last_watermark)
        VALUES ('orders', :watermark)
        ON DUPLICATE KEY UPDATE last_watermark = :watermark
    """), {
        "watermark": watermark.to_pydatetime()
    })
`}
/>

<Paragraph>After loading the new orders, <Highlight>save_watermark()</Highlight> moves the bookmark forward. It stores the newest <Highlight>updated_at</Highlight> value, and <Highlight>ON DUPLICATE KEY UPDATE</Highlight> replaces the existing bookmark instead of creating a second row. The <Highlight>to_pydatetime()</Highlight> call converts the pandas timestamp into a normal Python datetime for MySQL.</Paragraph>

<Paragraph>With the above two helper functions, we can use them in the incremental loading steps below.</Paragraph>

<CodeSnippet
  filename='load.py'
  code={`oldest_order_date = get_oldest_order_date(connection)
last_watermark = get_watermark(connection, oldest_order_date)

# Keep only orders modified after the last watermark.
orders = staging_tables["orders"]
orders = orders[orders["updated_at"].notna()
           & (orders["updated_at"] > last_watermark)]

`}
/>

<Paragraph>After loading the selected records, the watermark is updated.</Paragraph>

<CodeSnippet
  filename='load.py'
  code={`new_watermark = orders["updated_at"].max()
save_watermark(connection, new_watermark)
`}
/>

<Paragraph>This way, the pipeline focuses on new or modified orders instead of processing the entire orders dataset again.</Paragraph>

<Paragraph>This selects only records whose updated_at timestamp is later than the previous watermark.</Paragraph>

<Paragraph>For example, suppose our previous watermark is 2026-11-10 12:00:00.</Paragraph>

<H2>Handling Deleted Records</H2>

<Paragraph>Another important consideration in an ETL pipeline is handling deleted records.</Paragraph>

<Paragraph>For example, suppose a customer is removed from our source CSV. A normal UPSERT won't detect this deletion because it only inserts or updates records.</Paragraph>

<Paragraph>To handle this, we implement <Highlight>soft deletion</Highlight>. Instead of physically deleting records from the database, we use an is_deleted column to track their status.</Paragraph>

<BulletList items={[
  "**FALSE**: The record is active",
  "**TRUE**: The record has been marked as deleted"
]}
/>

<Paragraph>If a record is missing from the source. </Paragraph>

<CodeSnippet
  filename='load.py'
  lang='python'
  code={`UPDATE {table_name} t
LEFT JOIN current_keys c
    ON t.{key_column} = c.key_value
SET t.is_deleted = TRUE
WHERE c.key_value IS NULL
`}
/>

<Paragraph>If a previously deleted record appears again:</Paragraph>

<CodeSnippet
  filename='load.py'
  lang='python'
  code={`UPDATE {table_name} t
JOIN current_keys c
    ON t.{key_column} = c.key_value
SET t.is_deleted = FALSE
WHERE t.is_deleted = TRUE
`}
/>

<Paragraph>This allows us to retain historical records instead of permanently removing them. It also gives us a way to identify records that have disappeared and those that have returned.</Paragraph>

<H1>Bringing Everything Together</H1>

<Paragraph>Finally, we connect all three stages — <Highlight>Extract</Highlight>, <Highlight>Transform</Highlight>, and <Highlight>Load</Highlight> in a single <Highlight>main.py</Highlight> file.</Paragraph>

<Paragraph><Highlight>main.py</Highlight> is the entry point. It imports one function from each stage and calls them in order. <Highlight>extract_data()</Highlight> returns the source dataFrames, <Highlight>transform_data()</Highlight> returns the raw and staging tables, and the load functions write those tables into MySQL.</Paragraph>

<CodeSnippet
  filename='main.py'
  lang='python'
  code={`from extract import extract_data
from transform import transform_data
from load import load_all, load_incremental


def run_pipeline(load_mode="full"):
    # 1. Extract: read the CSV files.
    raw_data = extract_data()

    # 2. Transform: build the raw and staging tables.
    raw_tables, staging_tables = transform_data(raw_data)

    # 3. Load: write the tables into MySQL.
    if load_mode == "incremental":
        load_incremental(raw_tables, staging_tables)
    else:
        load_all(raw_tables, staging_tables)


if __name__ == "__main__":
    run_pipeline()
`}
/>

<Paragraph>This means we don't have to run each script separately. With just one command, the pipeline extracts the data, transforms it, and loads the results into MySQL.</Paragraph>

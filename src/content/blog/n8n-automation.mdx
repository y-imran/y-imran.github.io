<Paragraph>Every day, Tableau Public features a new <Highlight>Viz of the Day</Highlight> (VOTD), showcasing creative and insightful data visualizations from the Tableau community.</Paragraph>

<Paragraph>Lets build something that would automatically fetch each new Viz of the Day, generate a meaningful summary, and publish it on my LinkedIn account.</Paragraph>

<H1>Ideation</H1>

<Paragraph>The idea is very simple.</Paragraph>

<Figure src={AutomationFlow}/>

<Paragraph>A scheduled workflow scans Tableau Public daily for the latest Viz of the Day. New visualizations are stored, summarized by an AI agent, and automatically published to LinkedIn, while previously tracked vizzes have their engagement metrics updated.</Paragraph>

<Paragraph>That's how this project started.</Paragraph>

<H1>Why Did I Choose n8n?</H1>

<Paragraph>I chose n8n because it provides a visual, node-based approach to workflow automation.</Paragraph>

<Paragraph>Instead of writing an entire application from scratch, we could connect different services, APIs, databases, and AI models through individual nodes.</Paragraph>

<Paragraph>What made n8n particularly interesting for this project was its flexibility.</Paragraph>

<BulletList items={[
    "It supports HTTP requests to interact with external APIs",
    "It provides integrations with AI models and tools",
    "It allows conditional logic and data transformation",
    "It supports scheduled workflows",
    "It can connect directly to platforms such as LinkedIn"
]}/>

<Paragraph>Most importantly, we could build the workflow visually while still having the flexibility to write expressions and custom logic wherever needed.</Paragraph>

<H1>n8n Setup</H1>

<Paragraph>Before we begin, let's assume you already have n8n installed locally (via npm or Docker) and running successfully.</Paragraph>

<H1>Part 2: Storing VOTD Records and Tracking Engagement</H1>

<Paragraph>Once the VOTD data has been prepared, the next step is to maintain its records in the `viz_of_the_day` Data Table.</Paragraph>

<Figure src={Part2}/>

<Paragraph>The workflow then proceeds to maintain VOTD records and their engagement statistics by checking whether a visualization's curated date already exists and determining whether its record needs to be updated or newly inserted.</Paragraph>

<Paragraph>Let's break down how this works.</Paragraph>

<Highlight>4. Get VOTD Rows – Checking Existing Records</Highlight>

<Paragraph>The Get VOTD Rows Data Table node retrieves records from the `viz_of_the_day` table using the `curated_at` field.</Paragraph>

<Paragraph>Here, `curated_at` represents the date on which a visualization was featured as Viz of the Day.</Paragraph>

<Paragraph>The node uses the current VOTD's `curated_at` value as a filter to find whether a record for that date already exists in the table.</Paragraph>

<Paragraph>This helps identify whether the current visualization has already been recorded.</Paragraph>

<Highlight>5. Count – Counting Existing VOTD Records</Highlight>

<Paragraph>After retrieving the matching records, by using <Highlight>Summarize</Highlight> node we count the number of id values returned by the previous step.</Paragraph>

<Paragraph>The purpose is to determine how many matching VOTD records already exist.</Paragraph>

<Paragraph>For example</Paragraph>

<BulletList items={[
    "If the count is 1, a matching record exists",
    "If the count is 0, no matching record was found"
]}
/>

<Highlight>6. If – Deciding Whether to Update or Insert</Highlight>

<Paragraph>Now comes the conditional part of the workflow.</Paragraph>

<Paragraph>The <Highlight>If</Highlight> node checks whether the `id` count is greater than zero (id > 0).</Paragraph>

<Paragraph>Based on this condition, the workflow follows one of two paths</Paragraph>

<BulletList items={[
    "**True (id > 0)**: A record already exists in the Data Table, so its stats need to be updated",
    "**False (id = 0)**: No existing record was found, so a new VOTD record needs to be inserted"
]}
/>

<Paragraph>This conditional check ensures that existing records are updated instead of creating duplicate entries.</Paragraph>

<Highlight>6a. Update VOTD Stats – Tracking Engagement Over Time</Highlight>

<Paragraph>When a VOTD record already exists, the workflow updates its latest engagement statistics rather than overwriting the entire record.</Paragraph>

<Paragraph>To support future analysis, the Data Table contains separate columns for initial and latest engagement values. Initial values are preserved, while the latest values are refreshed whenever the scheduled workflow runs and retrieves updated statistics.</Paragraph>

<Paragraph>For example, columns such as initial_view_count and initial_reactions_love retain the engagement figures recorded when the VOTD was first added. Meanwhile, last_view_count and last_reactions_love are updated with the latest available values.</Paragraph>

<Paragraph>The Data table node (Update rows) is configured to update only the designated latest-value columns, leaving the remaining fields unchanged.</Paragraph>

<Paragraph>This allows the historical data to capture how engagement evolves over time</Paragraph>

<Highlight>6b. Insert VOTD Record</Highlight>

<Paragraph>When no matching record exists, the Insert VOTD Record node creates a new entry in the `viz_of_the_day` Data Table.</Paragraph>

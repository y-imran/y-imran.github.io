<Paragraph>Every day, Tableau Public features a new <Highlight>Viz of the Day</Highlight> (VOTD), showcasing creative and insightful data visualizations from the Tableau community.</Paragraph>

<H1>Ideation</H1>

<Paragraph>The idea is very simple.</Paragraph>

<Paragraph>Lets build something that would automatically fetch each new Viz of the Day, generate a meaningful summary, and publish it on my LinkedIn account.</Paragraph>

<Figure src={AutomationFlow}/>

<Paragraph>There are a couple of ways we can build this automation.</Paragraph>

<BulletList items={[
  "**Using a script**: We can write a script in **Python**, **JavaScript**, or any other programming language to fetch the latest Viz of the Day, generate its summary, and publish it on LinkedIn. We can then schedule the script to run automatically",
  "**Using an automation platform**: We can use a tool like **n8n** to automate the entire process by connecting different services and defining each step of the workflow visually"
]}
/>

<Paragraph>For this project, let's build it using n8n.</Paragraph>

<Paragraph>Why? Because it provides a visual, node-based approach to workflow automation, making it easier to understand, design, and manage the entire process. Its low-code approach also allows us to build automation without writing code for every step, making it accessible to non-technical users as well.</Paragraph>

<Panel type='info'>
Before we begin, let's assume you already have n8n running locally either via npm or Docker.
</Panel>

<H1>Step 2: Storing VOTD Records and Tracking Engagement</H1>

<Paragraph>Once the VOTD data has been prepared, the next step is to maintain its records in the <Highlight>viz_of_the_day</Highlight> table.</Paragraph>

<Figure src={Part2}/>

<Paragraph>The workflow then proceeds to maintain VOTD records and their engagement statistics by checking whether a visualization's curated date already exists or not.</Paragraph>

<Paragraph>Let's break it down one by one.</Paragraph>

<Highlight>4. Get row(s) – Checking Existing Record</Highlight>

<Paragraph>The Data table (Get rows) node retrieves records from the <Highlight>viz_of_the_day</Highlight> table using the <Highlight>curated_at</Highlight> field.</Paragraph>

<Paragraph>The node uses the current VOTD's <Highlight>curated_at</Highlight> value as a filter to find whether a record for that date already exists in the table or not.</Paragraph>

<Panel type='info'>
Enable <Highlight>Always Output Data</Highlight> in the Settings tab to ensure the workflow continues even when no matching record is found.
</Panel>

<Highlight>5. Summarize – Counting Existing VOTD Records</Highlight>

<Paragraph>THe <Highlight>Summarize</Highlight> node will count the number of <Highlight>id</Highlight> values returned by the previous step.</Paragraph>

<Paragraph>The purpose is to determine if VOTD records already exist.</Paragraph>

<Paragraph>For example</Paragraph>

<BulletList items={[
    "If the count is 1, a matching record exists",
    "If the count is 0, no matching record was found (this is only possible if **Always Output Data** is enabled in the previous node). "
]}
/>

<Highlight>6. If – Deciding Whether to Update or Insert</Highlight>

<Paragraph>Now comes the conditional part of the workflow.</Paragraph>

<Paragraph>The <Highlight>If</Highlight> node checks whether the <Highlight>id</Highlight> count is greater than zero (id > 0).</Paragraph>

<Paragraph>Based on this condition, the workflow follows one of two paths</Paragraph>

<BulletList items={[
    "**True (id > 0)**: A record already exists in the Data Table, so its stats need to be updated",
    "**False (id = 0)**: No existing record was found, so a new VOTD record needs to be inserted"
]}
/>

<Paragraph>This conditional check ensures that existing records are updated instead of creating duplicate entries.</Paragraph>

<Highlight>6a. Insert row(s)</Highlight>

<Paragraph>When no matching record exists, the Data table (Insert rows) node creates a new entry in the `viz_of_the_day` table.</Paragraph>

<Highlight>6b. Update row(s) – Tracking Engagement Over Time</Highlight>

<Paragraph>When a VOTD record already exists, the workflow updates its latest engagement statistics rather than overwriting the entire record.</Paragraph>

<Paragraph>To support future analysis, the table contains separate columns for initial and latest engagement values. Initial values are preserved, while the latest values are refreshed whenever the scheduled workflow runs and retrieves updated statistics.</Paragraph>

<Paragraph>For example, columns such as initial_view_count and initial_reactions_love retain the engagement figures recorded when the VOTD was first added. Meanwhile, last_view_count and last_reactions_love are updated with the latest available values.</Paragraph>

<Paragraph>The Data table node (Update rows) is configured to update only the designated latest-value columns, leaving the remaining fields unchanged.</Paragraph>

<Paragraph>This allows the historical data to capture how engagement evolves over time</Paragraph>

<H1>Part 3: Generating a Summary with AI</H1>

<Paragraph>Before sending data to the AI Agent, we need to make sure we haven't already generated a summary for the same Viz of the Day.</Paragraph>

<Paragraph>For this, we'll use a Data table (Get rows) node. It checks the summary_posting table using the <Highlight>curated_at</Highlight> field to determine whether a summary for the current Viz already exists or not.</Paragraph>

<Paragraph>We'll use this check to control the workflow.</Paragraph>

<BulletList items={[
  "**Matching record exists**: The summary has already been generated, so the workflow stops without executing the AI Agent",
  "**No matching record exists**: The workflow continues to the AI Agent, which generates a new summary. Once generated, we'll insert a new row into the **summary_posting** table to store the summary and curated_at"
]}
/>

<Paragraph>This check prevents duplicate summaries and ensures that we only generate content for new Vizzes of the Day.</Paragraph>

<H2>Equipping the AI Agent with Model and Tools</H2>

<Paragraph>Now let's look at how we can help our AI Agent understand each visualization.</Paragraph>

<H3>AI Model</H3>

<Paragraph>For the AI model, I'm using Ollama with, which allows us to run language models locally. I used <Highlight>glm-5.3</Highlight> as a language model. I've connected an Ollama Chat Model to the AI Agent, which will handle the summary generation using the information retrieved through the tools.</Paragraph>

<H3>AI Agent Tools</H3>

<Paragraph>We want the agent to understand what the visualization is about, explore its underlying data, and gather relevant information about its author.</Paragraph>

<Paragraph>For this, we'll connect several HTTP Request tools to our AI Agent. These tools allow the agent to retrieve additional information from Tableau Public whenever needed.</Paragraph>

<BulletList items= {[
  "**get-workbook-views**: This tool retrieves workbook metadata, including available worksheets, dashboards, and stories."
]}/>

<CodeSnippet
  lang="http"
  showLineNumbers={false}
  code={`https://public.tableau.com/profile/api/workbook/{workbook_repo_url}`}
/>
 <Paragraph>The response contains information about available views. Our agent can use this information to identify a relevant worksheet and retrieve its underlying data.</Paragraph>
